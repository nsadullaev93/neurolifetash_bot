# Журнал занятий — Telegram-бот + Mini App + Admin Panel

Проект состоит из трёх частей:

- **backend/** — сервер на Node.js/Express, Telegram-бот, планировщик напоминаний, база данных через Prisma
- **miniapp/** — Mini App для родителя (React + Vite), открывается кнопкой в боте
- **admin-panel/** — панель администратора (React + Vite), открывается в браузере отдельно

Всё работает **только на вашем компьютере** (localhost). Никакого хостинга не требуется.

Node.js, ngrok, все зависимости, база данных (миграция + начальные данные) уже установлены и настроены в этой сессии. ## 5. Запуск (три терминала)

**Терминал 1 — backend:**
```bash
cd backend
npm start
```
Появится: `Backend запущен: http://localhost:3000` и `Telegram-бот запущен (long polling)`.

**Терминал 2 — Mini App:**
```bash
cd miniapp
npm start
```
⚠️ Важно: используйте именно `npm start` (не `npm run dev`). На этом компьютере обычный dev-режим Vite отдаёт браузеру нетрансформированный код и показывает белый экран — это особенность окружения. `npm start` собирает проект (`vite build`) и сразу открывает его через `vite preview`, это работает надёжно. После правок в коде Mini App команду нужно перезапустить, чтобы пересобрать.

Откроется `http://localhost:5173` — можно сразу открыть в обычном браузере, работает без Telegram благодаря тестовому режиму входа.

**Терминал 3 — Admin Panel:**
```bash
cd admin-panel
npm start
```
Тот же нюанс — используйте `npm start`, не `npm run dev`. Откроется `http://localhost:5174`, войдите паролем из `.env`.

## 6. ngrok — чтобы Telegram видел Mini App

Telegram открывает кнопку Mini App только по адресу **https://**, поэтому нужен туннель ngrok на порт Mini App (5173).

**Терминал 4:**
```bash
ngrok http 5173
```
В выводе найдите строку вида `Forwarding https://ваш-адрес.ngrok-free.dev -> http://localhost:5173` и скопируйте `https://...` адрес.

Откройте `backend/.env`, вставьте этот адрес в `WEBAPP_URL`, сохраните, затем **перезапустите backend** (`Ctrl+C` в терминале 1, снова `npm start`).

**Важно:** бесплатный ngrok выдаёт новый адрес при каждом перезапуске туннеля — если перезапустили `ngrok http 5173`, повторите: обновите `WEBAPP_URL`, перезапустите backend, обновите ссылку в BotFather (раздел 7).

**Предупреждение ngrok при первом открытии.** Бесплатный ngrok иногда показывает страницу-заглушку «You are about to visit...» перед вашим сайтом — это стандартная страница ngrok для бесплатных аккаунтов, не ошибка. Нужно один раз нажать **Visit Site**.

## 7. Подключение Mini App к боту через BotFather

1. В Telegram откройте **@BotFather**, отправьте `/mybots`.
2. Выберите своего бота → **Bot Settings** → **Menu Button**.
3. Выберите **Configure menu button**, отправьте актуальный https-адрес ngrok.
4. Название кнопки — например, `Открыть журнал`.

**Альтернатива:** `/newapp` в BotFather → выбрать бота → пройти шаги (название, описание, картинка) → на шаге URL вставить тот же адрес ngrok.

## 8. Критически важно: открывайте бота на этом же компьютере

Mini App обращается к серверу по адресу `http://localhost:3000` — то есть **на том устройстве, где открыт Telegram**. Поскольку backend работает только на этом компьютере:

- ✅ Открывайте бота через **Telegram Desktop, установленный на этом же компьютере** — тогда `localhost` — это и есть этот компьютер, всё работает.
- ❌ Если открыть бота в Telegram на телефоне — Mini App попытается достучаться до `localhost` телефона, где backend не запущен, и ничего не загрузится.

Это следствие требования ТЗ «только localhost, без хостинга» — так и задумано для персонального использования одним человеком с одного компьютера.

## 9. Проверка, что всё работает

1. В Telegram Desktop на этом компьютере откройте бота, нажмите **/start**.
2. Нажмите кнопку меню — откроется Mini App (возможно, сначала страница-заглушка ngrok — нажмите Visit Site).
3. Отметьте занятие как «Было».
4. В Admin Panel (`http://localhost:5174`) → **Занятия** — убедитесь, что статус изменился.
5. Команды `/today` и `/balance` в боте должны присылать текстовые сводки.

## 10. Частые проблемы

**Mini App через `npm run dev` показывает белый экран / ошибку в консоли `Unexpected token '<'`**
Это особенность dev-сервера Vite на этой машине (см. раздел 5) — используйте `npm start` вместо `npm run dev`.

**Адрес ngrok сменился после перезапуска**
См. раздел 6 — обновите `WEBAPP_URL`, перезапустите backend, обновите ссылку в BotFather.

**Бот не отвечает на /start**
Проверьте терминал backend на ошибки о токене. Если `WEBAPP_URL` ещё `http://localhost` (ngrok не настроен) — бот всё равно ответит текстом, просто без кнопки (Telegram не принимает ссылки на localhost ни в каком виде кнопок).

**База данных недоступна / ошибки Prisma**
Проверьте `DATABASE_URL` в `.env`. Если проект Neon «уснул» — откройте neon.tech, это разбудит базу. Повторите `npx prisma generate`.

**Admin Panel просит пароль повторно**
Токен входа хранится в браузере 30 дней. После очистки данных браузера — войдите заново.

## 11. Ежедневное использование

1. `cd backend` → `npm start`
2. `cd miniapp` → `npm start`
3. Если нужен доступ из настоящего Telegram: `ngrok http 5173`, при смене адреса — обновить `WEBAPP_URL` и перезапустить backend
4. При необходимости: `cd admin-panel` → `npm start`

Открывайте бота только в Telegram Desktop на этом компьютере (см. раздел 8).
