# Деплой backend на Render.com — пошаговый план

Frontend уже задеплоен на Vercel и настроен на этот backend:

- Mini App: **https://miniapp-seven-nu.vercel.app**
- Admin Panel: **https://admin-panel-brown-three-79.vercel.app**

Обе переменные окружения (`VITE_API_URL`, `VITE_ADMIN_URL`) уже сохранены в настройках Vercel-проектов и указывают на backend по адресу `https://neurolifetash-backend.onrender.com` — поэтому важно назвать сервис на Render именно так (шаг 3), иначе адреса разойдутся и придётся их поправить вручную (см. раздел «Если назвали сервис иначе» в конце).

---

## 0. Важно прочитать перед началом: про бесплатный тариф Render

Backend — это не просто API, а ещё Telegram-бот (постоянно слушает сообщения через long polling) и планировщик (`node-cron`), который должен присылать напоминания **в конкретное время** (19:00, 1-го числа в 09:00 и т.д.).

**Бесплатный тариф Render («Free») «засыпает» после ~15 минут без входящих HTTP-запросов** — и вместе с этим останавливается весь процесс: бот перестаёт отвечать, напоминания не приходят, пока кто-то не «разбудит» сервис новым HTTP-запросом (с задержкой 30–60 секунд на пробуждение).

Для проекта, где важны напоминания точно по времени, это означает:
- **Free** — бот будет работать нестабильно: может не ответить на `/start`, если «уснул»; напоминания в 19:00 могут не прийти, если в этот момент сервис спал.
- **Starter (~7$/мес)** — сервис работает постоянно, бот и напоминания работают надёжно. Это рекомендуемый вариант для реального использования.

Решать вам — можно начать с Free, чтобы проверить, что всё разворачивается и работает, а затем переключиться на Starter в настройках сервиса (Render позволяет сменить тариф в любой момент без пересоздания сервиса).

## 1. Регистрация на Render

1. Откройте [render.com](https://render.com) → **Get Started**.
2. Войдите через **GitHub** (удобнее всего — тот же аккаунт `nsadullaev93`, под которым лежит репозиторий). Подтвердите доступ Render к вашим репозиториям.

---

## 2. Создание Web Service

1. В панели Render нажмите **New +** → **Web Service**.
2. Выберите **Build and deploy from a Git repository** → найдите и выберите `nsadullaev93/neurolifetash_bot`.
3. Нажмите **Connect**.

---

## 3. Настройка сервиса

На странице настроек укажите:

| Поле | Значение |
|---|---|
| **Name** | `neurolifetash-backend` (важно — от этого зависит адрес, см. врезку выше) |
| **Region** | любой ближайший (например, Frankfurt) |
| **Branch** | `main` |
| **Root Directory** | `backend` |
| **Runtime** | `Node` |
| **Build Command** | `npm install && npx prisma generate && npx prisma migrate deploy` |
| **Start Command** | `npm start` |
| **Instance Type** | `Free` (можно поменять позже) или `Starter` (рекомендуется, см. раздел 0) |

**Не добавляйте `PORT`** — Render назначает порт сам и передаёт его автоматически, сервер уже настроен это учитывать.

⚠️ **`ALLOW_DEV_LOGIN` обязательно должен быть `false`** на продакшене. Этот флаг локально позволял открывать приложение в браузере без входа через Telegram — в интернете это дыра в безопасности: кто угодно, узнав адрес, сможет читать и менять данные без авторизации.

Также стоит сменить `ADMIN_PASSWORD` на что-то менее предсказуемое, чем `admin123`, раз панель станет доступна из интернета — можно прямо сейчас вписать свой пароль вместо `admin123`.

## 5. Деплой

1. Нажмите **Create Web Service** внизу страницы.
2. Render начнёт сборку — это займёт 2–4 минуты. Следите за логами на вкладке **Logs**.
3. Дождитесь строк:
   ```
   Занятия на текущий месяц: создано ..., уже было ...
   Telegram-бот запущен (long polling)
   Backend запущен: http://localhost:XXXX
   ```
   Это значит backend и бот подняты.

---

## 6. Остановите локальный backend

**Прежде чем деплой на Render завершится и бот там запустится**, остановите backend, который сейчас работает у вас на компьютере (в терминале, где был запущен `npm start` в папке `backend`, нажмите `Ctrl+C`).

Telegram позволяет только одному процессу одновременно получать сообщения бота (long polling). Если два backend'а (локальный и на Render) работают одновременно с одним и тем же `BOT_TOKEN`, оба будут падать с ошибкой конфликта `409`.

Локальный ngrok-туннель тоже можно останавливать — он был нужен только для тестирования, теперь Mini App работает по постоянному адресу Vercel.

---

## 7. Обновите кнопку Mini App в BotFather

Адрес ngrok был временным и больше не будет работать. Обновите постоянную ссылку:

1. В Telegram откройте **@BotFather** → `/mybots` → выберите бота → **Bot Settings** → **Menu Button**.
2. **Configure menu button** → вставьте: `https://miniapp-seven-nu.vercel.app`

Теперь это постоянный адрес — обновлять его больше не нужно (в отличие от ngrok, который менялся при каждом перезапуске).

---

## 8. Проверка

1. Откройте вашего бота в Telegram (уже можно с **любого устройства**, не только с этого компьютера — теперь всё в интернете, а не на localhost).
2. `/start` → должна появиться кнопка, открывающая Mini App по адресу Vercel.
3. Откройте Admin Panel: `https://admin-panel-brown-three-79.vercel.app`, войдите паролем.
4. Отметьте занятие в Mini App → проверьте, что оно обновилось в Admin Panel.

## Если назвали сервис на Render иначе

Если вы назвали Web Service не `neurolifetash-backend`, а как-то по-другому, Render выдаст другой адрес (`https://ваше-имя.onrender.com`). В этом случае нужно поправить `VITE_API_URL` в обоих Vercel-проектах и передеплоить их. Пришлите мне итоговый адрес Render — я обновлю переменные в Vercel и передеплою фронтенды сам.

## Что дальше

- **База данных**: уже используется реальная Neon-база (та же, что и при локальной разработке) — данные не потеряются при переходе на Render.
- **Обновления кода**: раз GitHub-репозиторий подключён и к Vercel, и к Render — при каждом `git push` в `main` оба фронтенда и backend будут передеплоиваться автоматически.
- **Домены**: если захотите красивый домен вместо `*.vercel.app` / `*.onrender.com` — это отдельная настройка в каждой панели (Vercel → Settings → Domains, Render → Settings → Custom Domains), не обязательна для работы.
